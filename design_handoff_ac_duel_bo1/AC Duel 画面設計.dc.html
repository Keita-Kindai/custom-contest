DESIGN DOCUMENT / v0.1

AC Duel — 競技プログラミング対戦プラットフォーム 画面設計

AtCoder の過去問を使って「問題セットを作る → 友達と対戦する → 共有する」を回す日本語圏向けプラットフォームの画面設計。本ドキュメントの実装対象は 2人対戦 BO1 の MVP。サービス名は仮称。

Next.js / TypeScript / Tailwind 前提
データは全てモック
PC 1440 優先 / 別タブ併用
AtCoder の著作物・ロゴは不使用
00 / PREMISE

確認済みの前提と、置いた仮定

確認済み（回答より）
01提出は AtCoder の提出ページで行い、本サービスは判定をポーリングして表示する。コードエディタは持たない。
02問題文は表示せず、タイトル・Difficulty・外部リンクのみ。別タブで AtCoder を開く。
03相手について見せるのは、提出結果（AC / WA / TLE）・提出回数・経過時間とペナルティ。
04ログイン必須。ゲスト参加は無し。
05判定待ちは常駐ステータスとして自動更新。ユーザーによる「更新」操作は不要。
06対戦中画面はヘッダー＋常駐 HUD。フルスクリーンは取らず、ブラウザを分割して使える幅を保つ。
07問題は手動で選ばない。難易度帯（例: ABC の C〜E）を指定し、その範囲からランダムに抽選する。
08どちらか一方が AC した時点で対戦を終了する。
09Room の定員は 2 で固定。複数人のバーチャルコンテスト形式は将来案として分離する。
10問題データは AtCoder Problems の公開 API を前提とする。「全員が未 AC」条件は初期段階では扱わない。
仮定（未確認・変更容易）
Aログインはアカウント作成時に AtCoder ID を1つ紐付ける。判定の照合はその ID の提出一覧を見る前提。
BBO1 の制限時間は既定 30 分。Room 作成時に 10 / 20 / 30 / 45 / 60 分から選択。
C判定のポーリング間隔は 3 秒。UI 上の遅延許容は最大 10 秒とし、それを超えたら「取得が遅れています」を出す。
D勝敗判定は AtCoder 側の提出時刻を正とする。同秒に見える場合の扱いは 11 章に定義。
ERoom の定員は 2。Room ID は大文字英数字 6 桁（紛らわしい I / O / 0 / 1 を除く）。
FUI 言語は日本語のみ。用語（AC / WA / TLE / Difficulty）は英字のまま扱う。

操作
条件
結果と遷移
無効時の見せ方
Room を作る
ログイン済・出題範囲を選択済
Room ID を発行し Waiting へ。ID を自動でクリップボードにコピーし、トーストで通知。
範囲が未選択、または該当問題が 0 件なら押せない。理由を隣に表示。
参加する
6 桁が揃っている
照会 → Waiting へ。存在しない・満員・進行中は入力欄の下にエラーを出し、フォーカスは入力欄に残す。
桁が足りない間は非活性。形式エラーは入力中に出さない。
READY
2 人が在室
自分の状態を READY に。両者 READY で 0.5 秒後にカウントダウン開始。再押下で解除。
相手未参加なら「相手の参加を待っています」を表示して非活性。
カウントダウン
両者 READY
3 → 2 → 1 → START を各 1 秒。START と同時に問題を開示しタイマー開始。Esc で中断し両者の READY を解除。
中断時は「ホストがカウントダウンを止めました」を両者に表示。
問題 / 提出を開く
対戦中
別タブで開く（target=_blank rel=noopener）。開いた時刻を記録し、HUD に「問題を開いた」を残す。
開示前は伏せカードのまま押せない。
判定の取得
対戦中は常時
3 秒間隔で自動取得。新しい提出を検知したら WJ 行を先頭に追加し、確定で行を差し替える。手動更新の UI は置かない。
10 秒以上更新できない場合のみ「取得が遅れています」を出す。
AC の確定
いずれかが AC
どちらか一方が AC した時点で対戦を終了する。オーバーレイを 3 秒表示して結果画面へ。両者の提出時刻の差が 1 秒未満で判別できない場合のみ引き分け。
勝敗確定後の提出は履歴に残すが結果を変えない。
制限時間終了
残り 0
両者未 AC なら引き分け。残り 60 秒で HUD の数字を強調（点滅ではなく太字＋枠）。
終了直後に確定した WJ は、提出時刻が時間内なら有効。
投了
対戦中
確認ダイアログを 1 回。確定で相手の勝ち。Shift+Q でも同じダイアログを開く。
誤操作防止のため単独キーは割り当てない。
再戦
結果画面
同じ Room を再利用し、両者が承諾したら READY 前の状態に戻る。「別の問題で」を選ぶと問題だけ差し替える。
相手が退出済なら「Room ID を共有して待つ」に切り替わる。
キーボードとフォーカス
すべての操作は Tab で到達でき、フォーカスリングは 2px の #F4F1EE を outline-offset 2px で表示する。
ショートカットは対戦中のみ有効（O / S / L / Shift+Q）。入力欄にフォーカスがある間は無効。
オーバーレイ表示中はフォーカスを内側に閉じ込め、Esc で閉じられるものだけ Esc を受ける。
カウントダウンなどの自動遷移は、フォーカス位置を次画面の主要ボタンへ移す。
モーション
基本は 120ms / ease-out のフェードのみ。位置の移動は使わない。
カウントダウンの数字だけ 1 秒ごとのスケール（1.15 → 1.0）を許可する。
WJ の記号は 1.2 秒周期の透過アニメーション。点滅はここだけに限定する。
prefers-reduced-motion では、WJ は静止記号、カウントダウンは数字の差し替えのみにする。
12 / STATES

ローディング・エラー・切断状態

指定された 12 状態それぞれの文言・記号・復帰手段。文言は画面にそのまま使える形で書いている。

△Room が見つからない
「該当する Room がありません。ID を確認してください。解散されている可能性もあります。」
復帰 / 再入力・自分で作る
■Room が満員
「この Room は満員です（2 / 2）。」観戦は MVP 対象外のため、退出のみを提示する。
復帰 / 別の ID を入力・自分で作る
◌相手が未参加
空席スロットに「待機中」。Room ID とコピー操作を最も大きく置き、READY は非活性にする。
復帰 / ID をコピーして共有
…相手が READY していない
「mio_p の準備を待っています」。60 秒経過で「催促する」を出す（1 回のみ、押すと相手に通知）。
復帰 / 催促・READY を解除
◌相手が切断した
「mio_p の接続が切れました。復帰を 60 秒待機（残り 41 秒）」。タイマーは止めない。
結果 / 未復帰なら相手の不戦敗
◌自分が切断・再接続中
上端に固定バーで「接続が切れました。再接続中…（3 / 10）」。操作ボタンは非活性、時間表示は最後の値をグレーで保持。
復帰 / 自動再試行・手動で再読み込み
↻状態の再同期中
復帰直後・深いリンク経由の初回。HUD と提出ログをスケルトンにし、確定した値だけ順に差し替える。推測値は出さない。
所要 / 目標 1 秒以内・上限 5 秒
◐AtCoder からの判定待ち
WJ 行を常駐。10 秒以上更新がなければ「取得が遅れています。AtCoder 側の判定が混雑している可能性があります。」を追記。
復帰 / 自動・ユーザー操作は不要
✕WA / TLE / RE
記号と英字で区別し、右にペナルティを表示。失敗を強調する演出は入れず、行が 1 本増えるだけにする。
ペナルティ / 1 提出につき +1 分
◷制限時間終了
「時間切れです。両者未 AC のため引き分けとして記録します。」残り 60 秒からは数字を太字＋枠で強調する。
遷移 / 結果画面へ
＝同時 AC に見える場合
両者の提出時刻を並べて示し、差が 1 秒未満なら引き分け。どちらが先かを推測して表示しない。
記録 / DRAW として戦績に残す
■対戦が無効になった
「この対戦は無効になりました。判定を取得できず、戦績には記録されません。」原因（取得不能・両者切断・問題の非公開化）を 1 行で添える。
復帰 / 同じ設定でやり直す

モックデータの形
type Verdict = 'AC'|'WA'|'TLE'|'RE'|'CE'|'WJ' type RoomState = 'waiting'|'ready'|'countdown' |'live'|'result'|'void' type Player = { name, atcoderId, rating, ready, connection: 'online'|'offline'|'sync', submissions: Submission[] } type Submission = { index, verdict, at, lang?, detail?, penalty } type Pool = { contest:'ABC'|'ARC'|'AGC', slots: ('C'|'D'|'E')[], diffRange:[number,number] } type Match = { roomId, mode:'BO1', limitMin, pool, problem, startedAt, state: RoomState, outcome?: 'win'|'lose'|'draw'|'void' }
WebSocket は使わず、状態遷移はローカルの reducer とタイマーで再現する。判定取得も setInterval のモックで置き換える。問題の候補取得は AtCoder Problems の公開 API を想定し、開発中は固定 JSON で代替する。
実装順と受け入れ条件
1トークンとプリミティブ（VerdictBadge / DifficultyChip / StatusBanner）。全 verdict の表示が記号・英字・日本語の 3 点セットで出ること。
2Room の状態機械（waiting → ready → countdown → live → result / void）。URL クエリと状態が常に一致し、リロードで復元できること。
3対戦画面と HUD。1024px 幅でも崩れず、キーボードのみで問題・提出ページを開けること。
412 状態の再現。開発用のデバッグパネルから任意の状態に切り替えられること。
5結果と再戦。DRAW と VOID が結果画面で区別して表示されること。
検証は単体テストと E2E で行う。E2E では各状態のスクリーンショットを取得し、12 状態を一つずつ埋めていく。デバッグパネルから任意の状態を直接指定できることが前提になる。
本ドキュメントの数値（残り時間・Rating・件数）は全てモック値であり、実データの仕様ではない。
外部素材は使用していない。アバターは面のみのプレースホルダーで、実装時に差し替える。
AtCoder のロゴ・配色・画面構成は参照しておらず、問題への遷移は通常のリンクとして扱う。
