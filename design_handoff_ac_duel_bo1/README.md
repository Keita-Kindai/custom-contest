# Handoff: AC Duel — 2人対戦 BO1（MVP）

## Overview

AtCoder の過去問を使って「問題セットを作る → 友達と対戦する → 共有する」を回す日本語圏向けプラットフォーム。
この Handoff の実装対象は **2人対戦 BO1 の MVP** で、トップから Room 作成・参加・READY・カウントダウン・対戦・勝敗確定・結果・再戦までの一連の流れと、その異常系 12 状態。

サービス名「AC Duel」は仮称。

- 想定スタック: **Next.js (App Router) + TypeScript + Tailwind CSS**
- この段階では **バックエンド・認証・DB・WebSocket は実装しない**。状態はローカルの reducer とタイマーで再現し、データは全てモック。
- AtCoder のロゴ・配色・画面構成は参照していない。問題への遷移は通常の外部リンクとして扱う。

## About the Design Files

同梱の `AC Duel 画面設計.dc.html` は **HTML で作られたデザインリファレンス**です。本番コードとしてコピーするためのものではなく、意図した見た目・情報設計・状態遷移を示すプロトタイプです。

やってほしいのは、この HTML デザインを **対象コードベースの既存環境（Next.js / TypeScript / Tailwind）で作り直すこと**。既存のコンポーネント・命名・ディレクトリ構成・ユーティリティがあればそれに従ってください。まだ何も無い場合は Next.js + TypeScript + Tailwind で新規に構築して構いません。

ファイルはブラウザで直接開けます（`support.js` が同じディレクトリに必要）。1 枚の縦長デザインドキュメントで、以下の 14 章が上から順に並んでいます。

## 確定している仕様

1. **提出は AtCoder 上で行う。** 本サービスはコードエディタを持たない。「問題を開く」「提出ページを開く」は別タブ（`target="_blank" rel="noopener noreferrer"`）。
2. **判定はポーリングで取得。** 間隔 3 秒、自動更新のみ。手動更新の UI は置かない。10 秒以上更新できない場合だけ「取得が遅れています」を追記する。
3. **問題文は表示しない。** 表示するのは問題名・Difficulty・外部リンクのみ。
4. **出題はランダム抽選。** ユーザーは「コンテスト種別（ABC など）＋問題記号（C〜E）＋Difficulty 帯」を選ぶ。個別の問題は選ばない。抽選結果は START の瞬間に開示する。
5. **どちらか一方が AC した時点で対戦終了。** 提出時刻の早い側の勝ち。差が 1 秒未満で判別できない場合のみ引き分け。
6. **相手について見せる情報:** 提出結果（AC / WA / TLE / RE）・提出回数・経過時間・ペナルティ。コードと言語は共有しない。
7. **ログイン必須。** ゲスト参加は無し。
8. **Room 定員は 2 で固定。**
9. **対戦画面はヘッダー＋常駐 HUD。** フルスクリーンは取らない（AtCoder を別タブ／並べて使うため）。

### 仮定（変更しやすい・必要なら要確認）

- アカウントに AtCoder ID を 1 つ紐付け、判定照合はその ID の提出一覧を見る前提。
- BO1 の制限時間は既定 30 分（10 / 20 / 30 / 45 / 60 分から選択）。
- ペナルティは不正解 1 提出につき +1 分。
- 相手切断時の猶予は 60 秒。未復帰なら相手の不戦敗。
- Room ID は大文字英数字 6 桁（紛らわしい `I` `O` `0` `1` を除く）。
- 問題候補の取得は **AtCoder Problems の公開 API** を想定。開発中は固定 JSON で代替する。
- UI 言語は日本語のみ。AC / WA / TLE / Difficulty などの用語は英字のまま扱う。

## Screens / Views

### サイトマップ（MVP 部分）

```
/                        トップ（対戦開始 / セット導線）
/login                   ログイン（AtCoder ID 紐付け）
/battle/new              Room 作成（モード・時間・出題範囲）
/battle/join             Room ID 入力で参加
/battle/r/[roomId]       Room（?s=waiting|countdown|live|result）
```

Room の各状態は URL クエリで表現し、リロードと再接続で同じ状態に戻れること。深いリンクを踏んだ場合は状態を再同期してから描画する。

MVP 対象外（設計のみ存在）: `/sets/new`, `/sets/[setId]`, `/sets/mine`, `/discover`, `/u/[userName]`, `/settings`

---

### 01. トップ `/`

- **目的**: 対戦を始める / 参加する。
- **レイアウト**: 上部ヘッダー（ロゴ・ナビ・ユーザー）、中央にヒーロー（大見出し＋一行説明＋主 CTA 2 つ「Room を作る」「ID で参加」）、下部に「直近の対戦 3 件」「保存セット」。
- **状態**: 未ログイン / 初回（履歴なし）/ 通常。

### 02. Room 作成 `/battle/new`

- **目的**: 対戦条件を決めて Room を発行する。
- **フォーム項目**:
  - モード: `BO1`（選択済・固定）、BO3 / BO5 / Contest は非活性で表示（将来）
  - 制限時間: セレクト、既定 30 分
  - 出題: ● ランダム（既定） / ○ セットから（MVP では非活性）
  - 範囲: コンテスト種別（ABC）＋問題記号（C〜E のマルチ選択）＋Difficulty 帯（600–1400 など）
  - 注記: 「START 時に抽選 / 開始まで非開示」
- **主ボタン**: 「Room を作成」
- **状態**: 入力中 / 検証エラー（範囲未選択・該当 0 件）/ 作成中

### 03. Room 参加 `/battle/join`

- **レイアウト**: 縦中央寄せ。ラベル「Room ID を入力」、6 分割のコード入力、補助文「貼り付け可 / 大文字英数字 6 桁」、主ボタン「参加する」。
- **挙動**: 貼り付けで一括入力、小文字は自動で大文字化。6 桁揃うまで主ボタンは非活性。形式エラーは入力中には出さない。
- **エラー**: 見つからない / 満員 / 進行中 → 入力欄の下に表示し、フォーカスは入力欄に残す。

### 04–05. Waiting Room / READY `/battle/r/[roomId]?s=waiting`

- **レイアウト**: 上部に `ROOM  K7M2QX` ＋コピーボタン、中央に 2 スロット横並び（自分 / 相手）、下部に対戦条件のサマリ（`BO1 / 30分 / ABC C〜E から抽選`）。
- **自分スロット**: 実線枠、緑のサイドライン。**相手スロット**: 空席時は破線＋「待機中…」、参加後は実線＋青のサイドライン。
- **READY**: トグル。両者 READY で 0.5 秒後にカウントダウン開始。再押下で解除。相手未参加時は非活性＋理由表示。
- 相手が 60 秒 READY しない場合、「催促する」を 1 回だけ出す。

### 06. カウントダウン `?s=countdown`

- 中央に数字のみ（3 → 2 → 1 → START、各 1 秒）。数字は 1 秒ごとに scale 1.15 → 1.0。
- 問題は非開示（`ProblemCard revealed={false}`）。START と同時に開示しタイマー開始。
- `Esc` で中断 → 両者の READY を解除し「ホストがカウントダウンを止めました」を両者に表示。

- **WIN**: 12px 緑角丸 2px ＋ `WIN`（800 34px `oklch(.85 .13 145)`）／サマリ 2 行／「結果を見る」（緑）＋「再戦を申し込む」（枠）／「3 秒後に自動で結果画面へ」

### 09. 結果 / 再戦 `?s=result`

- 上部に `WIN 1 - 0`、中央に提出履歴の対比（自分 / 相手のタイム・提出回数・ペナルティ）、下部に「再戦」「別の問題で」。
- 「再戦」は同じ Room を再利用し、両者承諾で READY 前に戻る。「別の問題で」は抽選をやり直す。
- 相手が退出済なら「Room ID を共有して待つ」に切り替える。

## Interactions & Behavior

| 操作 | 条件 | 結果と遷移 | 無効時 |
|---|---|---|---|
| Room を作る | ログイン済・出題範囲を選択済 | Room ID を発行し Waiting へ。ID を自動でクリップボードにコピーしトースト通知 | 範囲未選択／該当 0 件なら非活性、理由を隣に表示 |
| 参加する | 6 桁が揃っている | 照会 → Waiting へ。不在・満員・進行中は入力欄の下にエラー、フォーカスは入力欄 | 桁不足なら非活性 |
| READY | 2 人が在室 | 自分を READY に。両者 READY で 0.5 秒後にカウントダウン。再押下で解除 | 相手未参加なら「相手の参加を待っています」＋非活性 |
| カウントダウン | 両者 READY | 3 → 2 → 1 → START（各 1 秒）。START で問題開示・タイマー開始。Esc で中断 | — |
| 問題 / 提出を開く | 対戦中 | 別タブで開く。開いた時刻を記録し HUD に「問題を開いた」を残す | 開示前は伏せカードで押せない |
| 判定の取得 | 対戦中は常時 | 3 秒間隔で自動取得。新規提出を検知したら WJ 行を先頭に追加し、確定で差し替える | 10 秒以上更新できない場合のみ警告を追記 |
| AC の確定 | いずれかが AC | **一方が AC した時点で終了。** 早い側の勝ち。オーバーレイ 3 秒 → 結果画面。差 1 秒未満なら引き分け | — |
| 制限時間終了 | 残り 0 | 両者未 AC なら引き分け。終了直後に確定した WJ は提出時刻が時間内なら有効 | — |
| 投了 | 対戦中 | 確認ダイアログ 1 回 → 相手の勝ち。`Shift + Q` も同じダイアログ | 誤操作防止のため単独キーは割り当てない |
| 再戦 | 結果画面 | 同じ Room を再利用、両者承諾で READY 前へ。「別の問題で」は抽選のみやり直す | 相手退出済なら共有待ちに切替 |

### キーボードとフォーカス

- 全操作は Tab で到達可能。フォーカスリングは `outline: 2px solid #F4F1EE; outline-offset: 2px`。
- ショートカット（`O` / `S` / `L` / `Shift+Q`）は対戦中のみ有効。入力欄にフォーカスがある間は無効。
- オーバーレイ表示中はフォーカスを内側に閉じ込め、閉じられるものだけ `Esc` を受ける。
- 自動遷移時はフォーカスを次画面の主要ボタンへ移す。

### モーション

- 基本は **120ms / ease-out のフェードのみ**。位置の移動は使わない。
- 例外 1: カウントダウンの数字（1 秒ごとに scale 1.15 → 1.0）。
- 例外 2: WJ 記号の透過アニメーション（1.2 秒周期、`opacity 1 → .35 → 1`）。点滅はここだけ。
- `prefers-reduced-motion` では WJ は静止記号、カウントダウンは数字の差し替えのみ。

### 状態の見せ方（12 状態・文言はそのまま使える形）

| 状態 | 記号 | 文言 / 挙動 | 復帰 |
|---|---|---|---|
| Room が見つからない | △ | 「該当する Room がありません。ID を確認してください。解散されている可能性もあります。」 | 再入力 / 自分で作る |
| Room が満員 | ■ | 「この Room は満員です（2 / 2）。」観戦は MVP 対象外 | 別 ID / 自分で作る |
| 相手が未参加 | ◌ | 空席スロットに「待機中」。Room ID とコピーを最大に、READY は非活性 | ID を共有 |
| 相手が READY していない | … | 「mio_p の準備を待っています」。60 秒で「催促する」を 1 回だけ | 催促 / READY 解除 |
| 相手が切断した | ◌ | 「mio_p の接続が切れました。復帰を 60 秒待機（残り 41 秒）」**タイマーは止めない** | 未復帰なら相手の不戦敗 |
| 自分が切断・再接続中 | ◌ | 上端固定バー「接続が切れました。再接続中…（3 / 10）」操作は非活性、時間は最後の値をグレーで保持 | 自動再試行 / 手動再読み込み |
| 状態の再同期中 | ↻ | HUD と提出ログをスケルトンに。確定した値だけ順に差し替え、**推測値は出さない** | 目標 1 秒 / 上限 5 秒 |
| 判定待ち | ◐ | WJ 行を常駐。10 秒以上更新がなければ「取得が遅れています。AtCoder 側の判定が混雑している可能性があります。」を追記 | 自動・操作不要 |
| WA / TLE / RE | ✕ / ◷ / ! | 記号と英字で区別、右にペナルティ。**失敗を強調する演出は入れず、行が 1 本増えるだけ** | +1 分 |
| 制限時間終了 | ◷ | 「時間切れです。両者未 AC のため引き分けとして記録します。」残り 60 秒から数字を太字＋枠 | 結果画面へ |
| 同時 AC に見える | ＝ | 両者の提出時刻を並べ、差 1 秒未満なら引き分け | DRAW として記録 |
| 対戦が無効 | ■ | 「この対戦は無効になりました。判定を取得できず、戦績には記録されません。」＋原因 1 行 | 同じ設定でやり直す |

**色だけに依存しない**こと。判定は必ず「記号・英字ラベル・日本語」の 3 点を併記する。AC のみ背景色を持ち、他は同一の面で記号と文字で区別する。

## State Management

```ts
type Verdict = 'AC' | 'WA' | 'TLE' | 'RE' | 'CE' | 'WJ'
type RoomState = 'waiting' | 'ready' | 'countdown' | 'live' | 'result' | 'void'
type Connection = 'online' | 'offline' | 'sync'

type Submission = {
  index: number
  verdict: Verdict
  at: number          // AtCoder 側の提出時刻（epoch ms）を正とする
  lang?: string       // 相手側は隠す
  detail?: string     // 「2 / 34 ケース」「2200 ms」など。相手側は隠す
  penalty: number     // 分
}

type Player = {
  name: string
  atcoderId: string
  rating: number
  ready: boolean
  connection: Connection
  submissions: Submission[]
}

type Pool = {
  contest: 'ABC' | 'ARC' | 'AGC'
  slots: ('C' | 'D' | 'E')[]
  diffRange: [number, number]
}

type Problem = {
  id: string          // 'abc302_c'
  contestLabel: string // 'ABC 302 C'
  title: string
  difficulty: number
  colorName: string   // '茶'
  tags: string[]
  problemUrl: string
  submitUrl: string
}

type Match = {
  roomId: string
  mode: 'BO1'
  limitMin: number
  pool: Pool
  problem: Problem | null   // countdown 完了まで null（非開示）
  startedAt: number | null
  state: RoomState
  outcome?: 'win' | 'lose' | 'draw' | 'void'
}
```

### 遷移

`waiting → ready → countdown → live → result | void`

- `waiting → ready`: 2 人在室かつ両者 `ready === true`
- `ready → countdown`: 0.5 秒後に自動
- `countdown → live`: 3 秒後（START）。ここで `problem` を確定し `startedAt` を打つ
- `countdown → ready`: Esc / READY 解除 / 切断
- `live → result`: いずれかの AC 確定・投了・制限時間終了
- `live → void`: 判定取得不能・両者切断・問題の非公開化
- `result → ready`: 再戦の両者承諾

### データ取得

- 判定ポーリング: 対戦中のみ 3 秒間隔。実装は `setInterval` のモックで置き換える。
- 問題候補: AtCoder Problems の公開 API を想定。開発中は固定 JSON。
- WebSocket は使わない。相手側の動きは開発用のデバッグパネルから手動で発火させる。

**デバッグパネルを必ず用意すること。** 12 状態と各 verdict、相手の提出・切断・AC を任意に発火できること。E2E とスクリーンショット取得がこれに依存します。

## Testing

- **単体テスト**: 状態機械（`waiting → … → result | void`）、勝敗判定（早い側 / 1 秒未満は引き分け / 時間切れ）、ペナルティ計算、Room ID の正規化。
- **E2E**: 12 状態それぞれをデバッグパネルから発火し、**スクリーンショットを取得して穴を埋めていく**進め方。1 状態 = 1 スクリーンショットを基本とする。
- **受け入れ条件（実装順）**
  1. トークンとプリミティブ（`VerdictBadge` / `DifficultyChip` / `StatusBanner`）— 全 verdict が記号・英字・日本語の 3 点セットで出る
  2. Room の状態機械 — URL クエリと状態が常に一致し、リロードで復元できる
  3. 対戦画面と HUD — 1024px 幅でも崩れず、キーボードのみで問題・提出ページを開ける
  4. 12 状態の再現 — デバッグパネルから任意の状態に切り替えられる
  5. 結果と再戦 — DRAW と VOID が結果画面で区別して表示される

## Assets
