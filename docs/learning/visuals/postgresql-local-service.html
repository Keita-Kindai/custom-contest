実際に起きたこと

database作成、migration、実DB test、LAN healthまで順に検証した。

`other`の読み方

Loaded=trueなのにPIDも終了codeもないため、Homebrewがrunning/stopped/errorへ分類できない状態。

launchctl print "gui/$(id -u)/homebrew.mxcl.postgresql@18" state = not running runs = 0 pended nondemand spawn = speculative

成功メッセージはreadinessではない。 必ずpg_isreadyかpsqlまで確認する。

やらないこと

  • data directoryを削除しない・既存clusterへinitdbしない
  • 生きていることを調べずpostmaster.pidやsocketを消さない
  • 通常停止にkill -9を使わない
  • Homebrew管理とpg_ctl直接起動を混在させない
  • LANへ5432を公開しない。外向きはNext.jsの3000番だけ
