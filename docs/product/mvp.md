# MVP scope

Status: Draft。画面設計とADR完了後に確定します。

## 最初の縦切り

Battle modeの1ラウンドを、AtCoder連携の代わりに開発用Fake ACで完走させます。

## 完了フロー

1. ホストがBo1のRoomを作る。
2. ゲストがRoom IDで参加する。
3. 両者がREADYになる。
4. カウントダウン後に問題が公開される。
5. 開発用操作で一方のACを通知する。
6. サーバーが勝者を確定し、両画面へ同じ結果を配信する。
7. 対戦結果を再表示できる形で保存する。

## 後続の追加順

1. AtCoder userscriptによるSubmission evidence受付
2. Bo3 / Bo5と次ラウンド遷移
3. 条件付き問題セット生成
4. Contest mode
5. 問題セット公開、検索、ブックマーク、いいね

## MVP期間の代替手段

- OAuth導入前は開発用プロフィールで参加者を識別する。
- AtCoder通知接続前はFake ACを使ってゲーム進行を検証する。
- 高度な推薦導入前は明示条件とseed付き乱択で問題を選ぶ。
- Redis導入前は単一リアルタイムプロセスをRoom状態の正本にする。
